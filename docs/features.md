# Minis Linux 功能说明

Minis Linux 是部署在自有 Linux 主机上的单用户 AI 助手。它在主机上管理会话、技能、记忆和工作区工具，并把模型请求发往你配置的服务。本文标注了新增功能所需的版本；可用版本见 [GitHub Releases](https://github.com/brucelau1987cn/minis-linux/releases)。

## 对话入口

### Telegram 私聊

通过一个专用 Bot 聊天、调用技能和管理记忆，不用切换模式。Minis 通过 Telegram Bot API 长轮询接收消息，不需要开放入站端口。只处理配置中指定账号发来的私聊文本，不接受群聊或转发消息。

在已配置的 Bot 私聊中发送 `/status` 检查消息收发，再发一句普通消息验证模型。`/status` 不调用模型。发送 `/help` 可以查看命令，`/new` 清除 Minis 本机的对话上下文。已保存的对话在服务重启后可继续，`/new` 不删除 Telegram 聊天记录。

### 查看进度与停止任务（v0.3 起）

Bot 接到任务后先发回执。模型请求在后台执行，等待时仍可发送 `/status` 查看当前阶段。任务结束后，`/status` 会显示上一次任务的结果状态。

开始保存和发送结果前，可用 `/stop` 放弃本轮。Minis 不保存被停止的对话，也不发送迟到的结果，但模型服务可能仍在处理已经发出的请求。在旧请求退出前，Bot 不执行或排队新的模型任务。已经开始发送的回复不能撤回。若要在任务进行中清空会话，先发送 `/stop`，再发送 `/new`。

### 交互式终端

安装后运行 `minis` 打开行式对话界面。首次启动可填写模型配置，也可预先提供 `MINIS_BASE_URL`、`MINIS_MODEL` 和 `MINIS_API_KEY`。终端与 Telegram 分别保存设置、工作区、会话和记忆，不会自动同步。发送 `/exit` 退出终端。

如果只想试界面，在解压目录中运行 `python3 minis_cli.py --demo`。该演示使用固定的本地响应，不调用模型，也不修改正式会话。

### 设置终端默认模型（v0.3 起）

退出当前终端对话后运行 `minis model`。先选已有网关或添加新网关，再输入关键词筛选模型，用 ↑↓ 移动、Enter 确认、Esc 取消。终端不支持此菜单时会改用编号选择。添加网关需要名称、OpenAI 兼容 Base URL 和 API Key，密钥不回显；已有网关沿用各自的凭据，添加另一个网关不会覆盖它。目录不可用时可手动输入模型 ID。选模只拉取目录，不调用推理接口，也不验证模型推理权限。

已配置网关时可直接运行 `minis model MODEL_ID`，在默认网关上保存指定模型，不请求模型目录；`minis model --show` 查看已保存的默认模型，不显示 API Key。新设置在下次打开 `minis` 时生效。更换默认网关时，Minis 会显示目标并提示已有对话和长期记忆可能随请求发送，只有确认后才保存。

终端对话中输入 `/model` 可从已配置网关选模型，或输入 `/model MODEL_ID` 在当前网关直接切换。下一条消息就用新模型，不写入默认设置，也不用退出会话。保留当前对话意味着**切换网关后，后续请求会将对话上下文发给新网关**；不想把旧对话发过去，可以先用 `/new` 清除会话。长期记忆仍保留，并可能随请求发出。以上操作不改变 Telegram 服务的配置。

## 技能、工作区与记忆

### 按需加载技能

技能是本机安装的 `SKILL.md` 文件，用来描述一类任务的处理步骤。Minis 先把技能目录提供给模型，模型需要时才读取正文。发送 `/skills` 查看已装技能；使用时可以直接提需求，不必先选择技能或切换模式。

例如，将脱敏的值班记录放入工作区后，在私聊中发送：

> 使用 `weekly-report` 技能读取 `handover.md`，按已完成、风险和下一步整理中文周报。缺少的信息标记为待确认。

仓库提供一个 [周报技能示例](../skills/weekly-report/SKILL.md)。默认 systemd 部署从 `/opt/minis-linux/skills/<名称>/SKILL.md` 加载技能。技能文本可以指导模型使用已有工具，但不会授予新权限；Minis 不执行技能附带的脚本。

### 只读工作区

Telegram 和 `minis` 交互式终端可以列出、读取各自专用工作区顶层的普通 UTF-8 文本文件。两种入口都不提供写文件或 Shell 工具。路径和文件类型由程序检查，模型不能通过文件名访问工作区外的资料。工作区权限限制不等同于操作系统级沙箱。

### 显式长期记忆

- `记住：周报用中文`：保存一条偏好。
- `查看记忆`：列出当前入口的记忆和编号。
- `忘记第 1 条`：删除对应编号的记忆。

普通对话不会自动写入长期记忆，`/new` 也不会清除它。记忆以明文保存在本机，后续模型请求会携带当前条目。删除记忆不会移除旧对话、Telegram 或模型服务已经保存的副本。

## 模型接入与数据边界

Minis 使用 OpenAI 兼容的 `POST /v1/chat/completions`，可连接 CLIProxyAPI（CPA），也可连接其他支持工具调用的兼容服务。配置包含 Base URL（例如 `https://api.example.com/v1`）、模型 ID 和普通调用 API Key。使用 CPA 时不要填管理密钥。

Minis 在 Linux 主机上执行工具并保存状态；模型推理由配置的服务完成。发送给模型的内容可包括当前对话、保存的记忆、技能正文和工具读取的文本。不要将密钥或不适合发给模型的资料放进工作区、技能或记忆。

## 部署与版本维护

- **常驻运行。** 安装向导注册 systemd 服务。Bot 以非 root 身份运行，可随系统启动，并在异常退出时按服务配置重启。
- **检查版本。** `minis --version` 显示已安装版本；`minis update --check` 查找更新，不安装或重启服务。
- **升级。** `minis update` 校验更新标签签名后安装较新的稳定版，不跟随开发分支。升级保留现有配置、凭据、技能和聊天数据。安装器在本机检查新服务启动，失败时尝试回退，强制中断后可按部署手册恢复。

首次安装、凭据保护、日志检查和回退步骤见 [systemd 部署手册](../systemd/README.md)。
